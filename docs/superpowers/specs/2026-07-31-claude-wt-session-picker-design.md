# Дизайн: пикер claude-wt сессий в GUI

Окно-палитра в духе Raycast/Alfred, которое показывает claude-wt сессии и
переключает на них. Открытые фокусируются, закрытые поднимаются заново.

Ссылки вида `windows.js:10` — на файлы `windows-mqtt`, если не сказано иное.
Соседний проект — `windows11-manager` (`D:\projects\js\windows11-manager`),
подключён как файловая зависимость.

## Зачем

Сейчас между claude-сессиями переключаются через Alt+Tab по неотличимым окнам
Windows Terminal. Вотчер claude-wt уже знает про каждую сессию имя, проект,
координаты и виртуальный десктоп — этого хватает на быстрый переключатель,
который ищет по имени проекта и не требует узнавать окно в лицо.

## Что уже есть

- Вотчер claude-wt работает внутри процесса Node windows-mqtt
  (`windows.js:22`, ключ `modules.windows.claudeWt`), состояние пишется раз в
  секунду в `claude-wt.json`.
- Между Node и Rust ходит построчный JSON: Node → Rust через stdout
  (`mqtt-bridge.js:71`, перечисление `IpcFromJs` в `main.rs:22`), Rust → Node
  через stdin (`stdin-handler.js:12`).
- GUI — один `index.html` с логом; webview получает строки лога событием
  `server-log` и умеет `invoke` в Rust.
- Глобальный хоткей регистрируется (`main.rs:726`), но жёстко шлёт
  `windows/autoplace`.
- Rust читает `config.yml` через `serde_yaml` (`main.rs:425`).

## Чего нет и придётся сделать

- **`winMan.focusWindow` не существует.** `windows.js:141` вызывает функцию,
  которой нет ни в одном файле windows11-manager: MQTT-топик `windows/focus`
  мёртв и падает на первом же сообщении. Фокус — центральное действие пикера,
  поэтому настоящий путь делается здесь: `Window.bringToTop()` и `restore()` из
  `node-window-manager`, переключение стола — `virtualDesktop.GoToDesktopNumber(n)`.
- **Нет API, отдающего сессии с хендлами окон.** `claudeWtStatus()` не отдаёт
  `cwd` и не знает `windowId`. `lastLayout` не годится как признак «открыта»: он
  хранит состав последнего тика *с окнами*, поэтому после закрытия всех
  терминалов продолжает перечислять их как живые. `openSessionIds()` даёт верное
  множество id, но без хендлов, а без хендла нечего фокусировать.
- **Действия в Node не принимают аргументов** — `handleAction(action)` получает
  голую строку.

## Решения

### Окна

Два независимых окна Tauri, переходов между ними нет ни в одну сторону.

| Окно | Что показывает | Вид |
| --- | --- | --- |
| `main` | лог, как сейчас | 800×600, с рамкой |
| `sessions` | пикер | `decorations: false`, `alwaysOnTop: true`, `skipTaskbar: true`, `resizable: false`, `visible: false`, ~720×480 |

Страница пикера — `sessions.html` рядом с `index.html`;
`scripts/prepare-frontend.js` копирует обе.

### Показ

Хоткей и пункт трея зовут одну функцию Rust `show_picker()`: берёт позицию
курсора, находит монитор под ней, считает центр, ставит окно туда, затем
`show()` и `set_focus()`. Позиция считается при каждом показе — центр нужен
именно активного монитора, поэтому `center: true` из конфига не подходит.

Скрытие: Esc, потеря фокуса, выполненное действие.

### Поток данных

1. Окно при показе зовёт `invoke('request_claude_sessions')`.
2. Rust отправляет в Node действие.
3. Node собирает список и пишет в stdout строку нового типа
   `{type:'event', name:'claude-wt-sessions', payload}`.
4. Rust добавляет вариант в `IpcFromJs` и эмитит Tauri-событие в окно `sessions`.
5. Webview слушает. Пока окно открыто, модуль `windows` повторяет отправку по
   своему таймеру раз в секунду; на скрытии окно зовёт `invoke`, который просит
   Node остановить отправку. Сам вотчер claude-wt про пикер ничего не знает.

Обратно: `{type:'action'}` и `handleAction` получают необязательное поле
`payload`, обработчики `stdinActions` — необязательный аргумент. Существующие
действия не меняются. Новые действия:

| Действие | Нагрузка | Что делает |
| --- | --- | --- |
| `windows/claude-sessions-start` | — | начать отправку списка, сразу и далее по таймеру |
| `windows/claude-sessions-stop` | — | прекратить отправку |
| `windows/claude-focus` | `{ id }` | сфокусировать окно сессии |
| `windows/claude-restore-one` | `{ id }` | поднять закрытую сессию |

Альтернативы отброшены. Чтение `claude-wt.json` напрямую из Rust требует
продублировать `statePath` в `config.yml` (он лежит в
`windows11-manager.config.js`, а это JavaScript, который Rust не парсит) и
переписать группировку по мониторам на Rust вторым экземпляром — ровно тот класс
связок, на который AGENTS.md уже жалуется про `paths.js` и `main.rs`.
Полноценный RPC с корреляцией по id — цена без покупателя: потребитель у данных
ровно один.

### Модель сессии

`{ id, title, cwd, bounds, desktop, monitor, open, windowId }`.

В windows11-manager добавляется `claudeWtSessions()`: сканирует терминалы как
`openSessionIds()`, но отдаёт полную запись на сессию, включая `windowId` для
открытых. Граница проводится там, где она уже проходит: сосед знает, какие
claude-сессии есть и где они, windows-mqtt занимается транспортом и интерфейсом.
Разбор заголовков терминалов на своей стороне не дублируется.

Монитор определяется **по центру окна**, а не по левому верхнему углу: окно на
стыке двух мониторов иначе уезжает не в ту группу, а при отрицательных
координатах — мимо всех. Номер берётся из `getMons()`, той же нумерации, что в
правилах размещения, чтобы «Monitor 2» в пикере и в конфиге значили одно.

### Вид и порядок

Группы: по десктопу, внутри — по монитору. Внутри группы сортировка по `x`, при
равенстве — по `y`. Закрытые сессии живут в тех же группах: координаты у них
есть, это последнее известное место.

Группы упорядочены по номеру десктопа, затем по номеру монитора. Сессии без
известного номера десктопа (`claudeWt.desktop: false` — тогда его никто не
читает) собираются в одну группу без номера, она идёт первой. Группа «Unknown
monitor» — последней внутри своего десктопа.

Строка: слева глиф-миниатюра монитора с закрашенным прямоугольником окна в
реальных пропорциях, дальше имя сессии и приглушённый `cwd`. У закрытых глиф и
рамка пунктиром.

Рассмотренные и отклонённые раскладки: пространственная мини-карта (плитки на
реальных местах монитора) плохо уживается с фильтрацией — при сужении выдачи
плитки нельзя убрать, не разрушив карту; компактная сетка равных карточек теряет
информацию о положении, которая здесь бесплатна.

Реальных копий окон не делаем. Захвата пикселей в проекте нет:
`@hurdlegroup/robotjs` умеет только `screen.capture()` — снимает экран, поэтому
отдаёт чужие пиксели для перекрытого окна и пустоту для окна на другом
виртуальном десктопе. Честный `PrintWindow` — это новый нативный код ради
украшения.

### Поиск

Поле сверху, фокус ставится при каждом показе окна. Фильтр по подстроке без
учёта регистра, одновременно по имени и по `cwd`. Группы без совпадений
исчезают целиком. Дебаунс не нужен — список в десяток строк.

Клавиатура: первый элемент выбран сразу, ↑/↓ ходят по отфильтрованному списку
сквозь границы групп, Enter выполняет действие, Esc закрывает. Мышь работает
параллельно.

### Действия

**Открытая сессия — фокус.** Пикер прячется первым, затем при отличии `desktop`
от текущего — `GoToDesktopNumber(n)`, дальше `restore()` для свёрнутого окна и
`bringToTop()`.

**Главный технический риск.** Windows разрешает вывести окно на передний план
только процессу, который владеет текущим передним окном или получил последний
ввод. В момент Enter передним владеет процесс Tauri, а фокусировать будет Node —
другой процесс; система это блокирует, вместо переключения мигает кнопка на
панели задач. Основной путь: Rust вызывает `AllowSetForegroundWindow(pid)` для
дочернего Node прямо перед отправкой команды. Запасной, если не сработает:
перенести сам вызов фокуса в Rust, где процесс уже имеет право. **Проверяется
первым, до всей отделки** — от этого зависит, состоится ли фича вообще.

**Закрытая сессия — восстановление.** `restoreClaudeSessions({ sessionIds: [id] })`.
Пауза `launchDelayMs` стоит между запусками, поэтому для одной сессии её нет, но
ожидание нового окна тянется до 30 секунд. Пикер прячется сразу — появившееся
окно терминала и есть обратная связь. Итог уходит в лог; на неудачу поднимается
тост через модуль `notify`, потому что молчаливый провал здесь хуже лишнего
уведомления.

### Конфиг

```yaml
picker:
  hotkey: 'Super+F10'   # Win+F10
tray:
  leftClick: picker     # picker | log
```

Плюс уже добавленный `modules.windows.claudeWt: true`. Оба новых ключа читаются
на стороне Rust. Хоткей вынесен в конфиг, а не задан константой: проверить,
доживает ли Win+F10 до приложения, можно только на живой системе, и менять его не
должно стоить пересборки. `register_shortcut` (`main.rs:726`) обобщается —
принимает действие параметром вместо зашитого `windows/autoplace`.

В рабочий конфиг (`%APPDATA%\windows-mqtt\config.yml`) ставится `leftClick: picker`.

## Отказы

- **claude-wt выключен или `statePath` пуст** — окно открывается и пишет причину
  текстом, а не показывает пустоту.
- **Node не ответил за 2 секунды** — «backend not responding» вместо вечного
  спиннера.
- **Нет `windows11-manager`** (он `optionalDependency`, модуль `windows` тогда не
  грузится) — `tray.leftClick: picker` откатывается на лог с записью причины в
  журнал.
- **Окно закрыли, пока список висел на экране** — перед действием проверяется
  `isWindow()` по сохранённому хендлу; мёртвый хендл означает, что сессия молча
  трактуется как закрытая и уходит по пути восстановления. Дешевле, чем поллинг
  ради свежести списка.
- **Одинаковые подписи.** В реальных данных уже есть два слота
  `obsidian-agent-base` с одинаковым `cwd`, один открыт, другой закрыт. При
  коллизии пары «имя + cwd» к строке добавляется короткий префикс id — иначе
  выбор между двумя визуально идентичными строками превращается в угадывание.
- **Окно вне мониторов** (координаты от отключённого экрана) не роняет
  группировку, а попадает в группу «Unknown monitor».

## Тесты

AGENTS.md разрешает только чистую логику, без запуска нативных бинарей. Вся
содержательная часть выносится в чистые функции:

- `groupSessions()` — десктопы, мониторы, порядок по `x` с добором по `y`, окно
  на стыке мониторов, отрицательные координаты, монитор не найден, десктоп
  неизвестен, порядок самих групп
- `filterSessions()` — регистр, совпадение по `cwd`, пустой запрос, ноль
  совпадений
- `labelSessions()` — префикс id при коллизии имени и проекта
- `handleAction(action, payload)` — обратная совместимость: действия без нагрузки
  работают как работали
- Rust: разбор нового варианта `IpcFromJs`, чтение `picker.hotkey` и
  `tray.leftClick` из YAML с дефолтами при отсутствии ключей

Фокус, восстановление и сканирование окон не тестируются — это нативные вызовы.

## Ручная проверка

1. `npm test` и `cd src-tauri && cargo check`.
2. Win+F10 — окно без заголовка появляется по центру монитора с курсором, курсор
   в поле поиска.
3. Ввод части имени проекта сужает список; ↑/↓ ходят по строкам, Esc закрывает.
4. Enter на открытой сессии переключает на её окно, в том числе с переходом на
   другой виртуальный десктоп.
5. Enter на закрытой сессии поднимает терминал; в логе — результат.
6. Левый клик по трею открывает пикер, пункт «Show App» — лог.

## Границы

Не входит: реальные превью окон, закрытие сессий из пикера, мультивыбор,
переупорядочивание, вызов пикера по MQTT, изменение поведения существующих
MQTT-топиков.
