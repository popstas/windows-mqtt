# ccfzf-picker: менеджер сессий на macOS

## Problem

Пикер сессий claude-wt существует только на Windows и завязан на неё дважды:
список строится из `state.slots` — состояния оконного трекера в
windows11-manager, — а данные читаются с SMB-диска `V:`, откуда родом целый
класс багов (врущий `mtime`, чтение поколением назад, 300 мс на
`claudeWtSessions()`).

Главный сценарий, ради которого нужен мак: **сессия остановилась на Windows и
чего-то ждёт — вопрос, подтверждение, проверку, — а ответить хочется с мака, той
же сессии.** Такая сессия на pc-virt жива: процесс `claude` ждёт ввода в
ssh-соединении с Windows-машины. Второй `claude --resume` поверх неё дал бы два
процесса на одном транскрипте.

Отслеживание окон на маке не нужно.

## Solution

Новый кросс-платформенный репозиторий **`ccfzf-picker`** — Tauri-приложение,
куда переезжает вся claude-часть пикера из windows-mqtt. Данные — из одного
ssh-вызова к агрегатору на pc-virt, без монтирования файловой системы. Открытие
сессии — подключаемая стратегия, выбираемая по состоянию сессии.

Первый этап — только macOS. Windows остаётся на windows-mqtt и переводится
отдельным спеком, когда новый пикер докажет, что живой.

## Архитектура

Три слоя с жёсткими границами.

**Фронтенд (JS, `frontend-src/`)** — всё, что знает про сессию как про строку:
группировка, сортировки, склейка сводки, возраст, статус агента, подмена
родителя фоновым агентом, выбор стратегии открытия. Сюда переезжают чистые
функции вместе со своими тестами:

| Откуда | Что |
|---|---|
| windows11-manager `src/claude-wt/` | `progress-helpers`, `view-helpers` (`activeAgent`, `buildSessionList`), `sessions-helpers` |
| windows-mqtt `src/picker/` | `session-groups`, `format-age`, `pr-url`, `session-open-helpers`, `sessions-sort-config` |
| windows-mqtt | `sessions.html`, `frontend-src/picker-list-sync.js` |

**Rust (`src-tauri/`)** — окно пикера, глобальные хоткеи, запуск процессов,
транспорт до pc-virt. Про сессии не знает ничего: получил JSON — отдал во
фронтенд.

**Агрегатор на pc-virt** — одна команда, возвращающая всё, что знает
Linux-сторона, одним JSON.

Node-слоя нет. Всё, что раньше требовало node на стороне пикера, сводится к
одному ssh-вызову, а логика строки живёт во фронтенде.

### Границы наружу

| Что | Где живёт | На маке |
|---|---|---|
| Список сессий, сводки, стоимость, контекст | агрегатор на pc-virt | есть |
| Фокус живого окна WT, слоты, snapshots, restore | остаётся в windows11-manager | нет источника |
| MQTT, экспорт в Home Assistant, панель openHASP | остаётся в windows-mqtt | нет |

Оконное подключается как **необязательный источник**. Фронтенд получает
`windows: null` и не рисует того, чего нет: номер монитора, виртуальный стол,
действие «сфокусировать окно». Ровно это и делает mac-версию первой — Windows
подключается вторым этапом, ничего не ломая по дороге.

## Агрегатор

Новый флаг `ccfzf --state` рядом с существующим `--dump`: пишет один JSON в
stdout и ничего не кладёт на диск. Файлы читаются локально, где `mtime` не врёт и `stat`
стоит микросекунды, — весь класс багов с кэшем SMB на маке не заводится вовсе.

```json
{
  "generated": 1785858452.9,
  "sessions": [{
    "id": "...", "cwd": "...", "title": "...", "gist": "...", "doing": "...",
    "mtime": 1785858452.9, "live": true, "frozen": false,
    "kind": "interactive", "parent": "",
    "pid": 1626189, "tty": "pts/1", "tmux": null,
    "agent": { "event": "...", "summary": "...", "prompt": "...",
               "updated": 1785858452, "cost": 0.42, "context": 31 }
  }]
}
```

Новые поля против текущего дампа:

- `pid`, `tty` — чем сессия занята и можно ли её перехватить. `live_ids()` в
  ccfzf уже перебирает `/proc` и знает pid — сейчас он его выбрасывает.
- `tmux` — координаты панели (`session:window.pane`), если сессия внутри tmux,
  иначе `null`.
- `agent` — склеенные `<id>.state.json` и `<id>.status.json`, то самое слияние,
  которое сейчас делает `loadProgress()` через сеть.

Ответ **сырой, а не готовый к отрисовке**: `kind`, `parent` и `agent` уходят как
есть, а `activeAgent()` и `buildSessionList()` работают уже во фронтенде. Иначе
отлаженная логика фонового агента переписалась бы на Python вместе со всеми
своими граблями.

Транспорт — `ssh` с `ControlMaster=auto` и `ControlPersist`: один
переиспользуемый канал. Опрос раз в секунду **только пока пикер открыт**.

## Открытие сессии

Способ открытия — не константа, а выбор по состоянию сессии. Чистая функция
`chooseOpenStrategy(session, caps)` во фронтенде, где `caps` — что умеет
удалённая сторона (`{ reptyr: boolean }`, из конфига после эксперимента).
Четыре исхода:

| Состояние | Стратегия | Что происходит |
|---|---|---|
| `tmux != null` | **attach** | `kitty ssh -t <host> tmux attach -t <target>` — тот же экран, ничего не трогается |
| `live`, без tmux, reptyr доступен | **reptyr** | `kitty ssh -t <host> reptyr -T <pid>` — процесс переезжает в терминал мака |
| `live`, без tmux, reptyr недоступен | **takeover** | сигнал процессу, ожидание смерти, затем resume |
| не `live` | **resume** | `kitty ssh -t <host> 'cd <cwd> && claude --resume <id>'` |

Первые три закрывают главный сценарий, четвёртая — всё остальное. Функция чистая
и покрывается тестами целиком, поэтому решение, какую ветку взять, не
размазывается между Rust и UI.

### Takeover

Единственное необратимое действие в приложении, и оформляется как таковое:

1. Подтверждение с явным текстом — какой pid, какое окно на Windows схлопнется.
2. `SIGHUP` (не `-9`).
3. Ожидание ухода процесса с таймаутом и проверка, что он ушёл.
4. Только после этого — resume.

Отдельное предупреждение в подтверждении: у сессии могут быть фоновые задачи в
её шелле — в дампе на момент дизайна висели `ralphex` и `tail -f`, — они умрут
вместе с ней.

### Эксперимент с reptyr

**Идёт первым шагом плана, до постройки приложения.** Результат ни на что больше
не влияет: не взлетит — строка `reptyr` исключается из таблицы, остальные три
стратегии работают.

Состояние pc-virt на момент дизайна: reptyr не установлен,
`kernel.yama.ptrace_scope = 1`, tmux установлен, живые сессии — Node с 21–32
потоками (`claude -n ExpertizeMe`, pid 1626189, 32 потока). Процесс не лидер
сессии (родитель — zsh под ssh), поэтому нужен `reptyr -T`, который крадёт весь
терминал у предка.

Критерии успеха заданы заранее:

- TUI перерисовался в терминале мака;
- ввод доходит, ход доводится до конца;
- хуки продолжают писать `<id>.state.json`;
- старый ssh, умирая, не уносит процесс с собой;
- `Ctrl+C` не разваливает сессию.

Прогнать дважды: на сессии, ждущей ввода, и на сессии в середине хода.

`ptrace_scope=0` на время опыта ставится временно (`sysctl -w`). Постоянным
(`/etc/sysctl.d`) он становится только если опыт удался: это ослабление
локальной защиты — любой процесс пользователя сможет ptrace'ить любой другой, —
и платить им за неработающую функцию незачем.

## Приложение на маке

**Окно.** Глобальный хоткей поднимает пикер поверх всего, `Esc` закрывает,
повторное нажатие — тоже, с тем же ограничителем дребезга, что и `toggle_picker`
сейчас. Дефолт хоткея — `Cmd+Shift+T`, меняется в конфиге.

**Терминал.** Открытие всегда в новом окне kitty: `open -na kitty --args …`.
Переиспользование окна через `kitty @ launch` — не в v1.

**Конфиг** — `~/.config/ccfzf-picker/config.yaml`: `sshHost`, команда терминала,
список проектов с хоткеями, сортировка, чекбоксы statusline. Проекты задаются
здесь, а не тянутся из `claudeWt.projects` на Windows: та машина не обязана быть
включённой, а список из пары строк дублировать дешевле, чем зависеть от неё.

**Прочитанное** — `~/.config/ccfzf-picker/seen.json`, `id → focusedAt`. Отметка
ставится в момент открытия сессии. `seenSinceUpdate()` переиспользуется как
есть, меняется только источник отметки. Состояние у каждой машины своё:
прочитанное на маке останется непрочитанным на Windows — осознанная плата за
отсутствие общего хранилища.

**Живые сессии помечены в списке** — чтобы заранее было видно, что открытие
потребует attach, reptyr или перехвата, а не тихого resume.

**Меню действий (Ctrl+K):** Open PR, Session info, Mark unread. Пункты, которым
нужен локальный путь к файлам (Open in Cursor, Open in Explorer), в v1 не
входят.

**Проектные хоткеи** — аналог Ctrl+F11/F12: глобальный хоткей открывает новую
claude-сессию в заданном проекте, мимо списка.

## Монтирование pc-virt:/home/popstas

Для работы пикера монт не нужен ни в каком виде: данные идут по ssh, открытие
идёт по ssh. Это и есть ответ на вопрос «что лучше переживает автоподключение» —
лучше всего переживает его отсутствие.

Если монт нужен для ручной работы с файлами:

- **sshfs** тянет macFUSE — kernel extension. На Apple Silicon это Reduced
  Security и загрузка в recovery, и оно ломается на каждом крупном обновлении
  macOS. После сна соединение рвётся, точка монтирования становится мёртвой:
  процессы, зашедшие в неё, виснут намертво, снимается только
  `diskutil unmount force`. Автореконнект есть в опциях, но ненадёжен.
- **SMB** нативен и через `autofs` (`/etc/auto_master`) монтируется по
  требованию, перемонтируется после разрыва сам, мёртвых точек не оставляет.
  Лучший из двух по критерию «переживает сон».

Выбор: SMB через autofs. Но он принесёт те же грабли, что уже описаны в скилле
`claude-wt` про диск `V:` — врущий `mtime` и чтение поколением назад, — поэтому
источником данных для чего-либо автоматического он быть не должен.

Для «открыть проект в редакторе» правильный ответ не монт, а **Remote-SSH в
Cursor/VS Code**: файлы читаются на той стороне, после сна ничего не
разваливается.

## Не входит в v1

Уведомления «сессия ждёт ответа»; отслеживание окон на маке; snapshots и
restore; MQTT и панель openHASP; перенос Windows-стороны на новый пикер;
`kitty @ launch`; общее хранилище прочитанного между машинами; пункты меню,
требующие локального пути к файлам.

## Тестирование

- Чистые функции — юнит-тестами, как сейчас в windows11-manager:
  `chooseOpenStrategy`, склейка сводки, `activeAgent`, группы, сортировки,
  возраст, разбор PR.
- Агрегатор — тестом на форму ответа.
- Транспорт, Rust, глобальные хоткеи — вручную, как и сейчас.
- Эксперимент с reptyr — по критериям из раздела выше, до постройки приложения.
